Screen readeri — glas koji čita web

Screen reader je softver koji čita DOM strukturu naglas. Ne čita vizuelni izgled — čita semantiku. Zato semantic HTML nije estetski izbor, to je pitanje da li neko uopšte može koristiti tvoj sajt.

// lična priča

Znam programera koji je oslepeo sa 27 godina. Danas ima skoro 50 — i već 15 godina programira vrlo uspješno. Ne radi frontend, ali upravo govorne aplikacije koje čitaju interfejs pomažu mu da razume kod, da navigira IDE-ом, da čita dokumentaciju, da razume stranice.

Kada mu pošalješ API dokumentaciju bez dobre strukture headinga, bez alt tekstova, bez aria labela — za tebe je to "loša dokumentacija". Za njega je to neprohodna šuma bez putokaza.

Accessibility nije checkbox na kraju projekta. To je odluka doneta na početku, u strukturi HTML-a. I kada je doneta dobro — pomaže svima, ne samo slepima.

Windows

NVDA & JAWS

NVDA — besplatan, open source. Standard za Windows korisnike. Čita DOM, forme, tabele, dinamički sadržaj (ARIA live regions).

JAWS — Job Access With Speech. Profesionalni, skup (~1000$/god). Dominantan u korporativnom i vladinim sektoru.

NVDA besplatan JAWS profesionalni
Apple / Android

VoiceOver & TalkBack

VoiceOver — ugrađen u macOS, iOS, iPadOS. Potpuno besplatan. Najkoriščeniji screen reader na mobilnim uređajima.

TalkBack — Google, ugrađen u Android. Isti princip — čita semantiku, ne piksel.

// zakonski standard

WCAG — Web Content Accessibility Guidelines

W3C standard od 1999. Četiri principa — POUR:

P — Perceivable

Dostupno čulima

Sadržaj mora biti dostupan bar jednim čulom. Alt text za slike (vid → sluh). Titlovi za video. Kontrast teksta.

O — Operable

Operabilno

Sve mora raditi sa tastaturom. Bez zamki za fokus. Dovoljno vremena za čitanje. Bez epileptičnih okidača.

U — Understandable

Razumljivo

Jezik stranice deklarisan (lang="sr"). Greške u formama jasno objašnjene. Konzistentna navigacija.

R — Robust

Robustno

Radi sa assistive tehnologijama. Validan HTML. ARIA samo kad je potrebno. Semantic first.

// WCAG kontrast zahtev — 4.5:1 za normalan tekst
WCAG FAIL 3.8:1
Ovo je tekst koji nije dovoljno kontrastan. Teško čitljivo za ljude sa slabijim vidom.
WCAG AA ✓ 7:1
Ovo je tekst sa dovoljnim kontrastom. Čitljivo za većinu korisnika.
WCAG FAIL 2.1:1
Dark mode greška — sivi tekst na tamnoj pozadini. Čest problem.
WCAG AA ✓ 12:1
Dark mode ispravno — svetao tekst na tamnoj pozadini.

Vizuelna pristupačnost

Disleksija

OpenDyslexic & Lexend

Fontovi dizajnirani da smanje "preokretanje" slova. Teža dna slova pomažu mozgu da ih razlikuje. Lexend font — Google Fonts, besplatan. Klikni "Aa Disleksija" gore da testiraš ovu stranicu.

Kontrast teme

High Contrast Mode

Windows High Contrast, macOS Increased Contrast. Sajt mora raditi — ne može se osloniti na slike i gradijente za prenošenje informacija. Klikni "Visoki kontrast" gore.

Windows HCM prefers-contrast forced-colors
Zoom & Resize

200% zoom mora raditi

WCAG 1.4.4: tekst mora biti čitljiv na 200% zuma bez horizontalnog skrolovanja. Responsive design je accessibility. Fluid layout je accessibility.

Ctrl+= / Cmd+= rem umesto px Fluid layout
💡
Accessibility pomaže svima, ne samo osobama sa invaliditetom: Subtitlovi pomažu gledaocima u buci ali i onima koji uče jezik. Visoki kontrast pomaže onima na suncu sa lošim ekranom. Keyboard navigacija pomaže power userima koji ne vole miš. Alt text pomaže kada slika nije učitana na sporom internetu. Semantic HTML pomaže i SEO robotima — i screen readerima.

Zakonska obaveza — državni sajtovi

EU — 2016

Web Accessibility Directive

Direktiva EU 2016/2102 — svi državni i javni sajtovi moraju biti WCAG 2.1 AA kompatibilni. Obavezna izjava o pristupačnosti na svakom sajtu. Rok: javni sektor od 2019, mobilne aplikacije od 2021.

Obavezno za javni sektor WCAG 2.1 AA minimum
SAD — ADA tužbe

Americans with Disabilities Act

Domino's Pizza — tuženi jer slepa osoba nije mogla naručiti pizzu online. Amazon, Netflix, Harvard — sve tuženi. Svake godine hiljade tužbi. Sud je odlučio: web je "mesto javnog smještaja" pod ADA.

Domino's Pizza tužba Hiljade slučajeva/god
⚠️
Srbija i region: Zakon o sprečavanju diskriminacije lica sa invaliditetom propisuje pristupačnost digitalnih servisa. Državni portali (eUprava, poreska uprava) imaju obavezu WCAG usklađenosti. U praksi — retko se primenjuje strogo, ali trend ide ka obaveznoj primeni.
// frontend kao ključ za razumevanje backenda

Swagger — zašto bez FE nema ni razumevanja BE

Ovo je često zanemarena istina: backend API bez frontend prezentacije je neupotrebljiv za ljude. JSON endpoint koji vraća 47 polja — ko to razume? Swagger UI pretvara API specifikaciju u interaktivnu dokumentaciju. To je frontend koji čini backend razumljivim.

swagger
Ravanelius Competition API — v1.0
GET /api/participants Lista svih prijavljenih učesnika
POST /api/participants/register Prijava novog učesnika
GET /api/participants/{id} Detalji jednog učesnika
PUT /api/participants/{id} Ažuriranje podataka
DELETE /api/participants/{id} Brisanje prijave
Swagger UI — klikni na endpoint da vidiš parametre, schema, test "Try it out" dugme
🔌
Bez Swagger UI: developer otvori Postman, pogodi URL, pogodi parametre, čita izvorni kod da sazna šta API vraća. Sat vremena istraživanja za svaki novi endpoint.
✅
Sa Swagger UI: otvori browser, vidi sve endpointe, klikni "Try it out", pošalji request, vidi response. Pet minuta do razumevanja celog API-ja. FE čini BE razumljivim.
🎯
Ista filozofija svuda: CLI alati imaju --help — to je njihov "frontend". Git ima git log --oneline --graph — vizuelni frontend za historiju. Docker Desktop je frontend za Docker daemon. Kubernetes ima dashboard. Svaki složen sistem treba prezentacioni sloj da bi bio razumljiv. To je posao frontend developera — i uvek će biti.

Kada se počelo primenjivati

1995 — Pioniri

Alt text i tabindex

HTML 2.0 uvodi alt atribut za slike. Tad su ga koristili jer je internet bio spor — tekst se učitava brže od slike. Accessibility i performance — ista odluka, različiti razlozi.

1999 — Standard

WCAG 1.0

W3C objavljuje prvi WCAG standard. 14 smernica. Malo ko ga primenjuje — obaveze nema, alati ne postoje. Accessibility je "nice to have".

2008 — Zreoost

WCAG 2.0 — POUR

Četiri principa: Perceivable, Operable, Understandable, Robust. ARIA specifikacija. Screen readeri postaju moćniji. Accessibility počinje biti deo tender zahteva.

2016 — Zakon

EU Direktiva — obaveza

Pristupačnost postaje zakonska obaveza u EU. WCAG 2.1 (2018) dodaje mobile accessibility. WCAG 2.2 (2023) dodaje cognitive accessibility. WCAG 3.0 u razvoju.
